Bütün adımları yazı olarak göster
  1. Komut: M33’ü başlat

    Kartta state dosyasına start yazıldı. Çekirdekteki remoteproc sürücüsü bunu alır.

    Neden? remoteproc, Linux’un diğer işlemcileri (burada M33) yükleyip başlatan parçasıdır.

    remoteproc remoteproc1: powering up m33
  2. ELF dosyası okunur, tablo aranır

    Linux ELF dosyasının içinde .resource_table adlı bölümü arar. M5 programında yoktu; Adım 2’de eklendi.

    Neden? M33 “bana ne lazım” bilgisini bu tabloyla Linux’a verir. Tablo yoksa kanal hiç kurulmaz.

    M5: no resource table found for this firmware Adım 2’den sonra: bu satır yok
  3. Tablo okunur: 1 RPMsg aygıtı

    Tabloda “tip 7 (RPMsg), 2 vring, vring başına 8 tampon” yazıyor. Vring adresleri FFFFFFFF, yani “adresi sen seç”.

    Neden? Adresleri Linux seçer, çünkü paylaşılan belleğin sahibi Linux’tur.

    rproc-virtio rproc-virtio.3.auto: assigned reserved memory node vdev0buffer@812fa000
  4. Paylaşılan bellek ayrılır

    Linux, device tree’deki hazır alanları kullanır: vring0, vring1 ve tampon alanı. Adım 1’de bu adresleri kartta doğruladık.

    Neden? Bu alanlar Linux’un kullanmadığı, ayrılmış belleklerdir; yanlış adres Linux’un verisini bozardı.

  5. Program SRAM2’ye kopyalanır

    Linux ELF’in bölümlerini SRAM2’ye (0x0A060000) yazar. M33 hâlâ durmuş durumda.

    linux/drivers/remoteproc/remoteproc_core.c
    1275ret = rproc_load_segments(rproc, fw);
  6. Adresleri dolu tablo da kopyalanır

    Linux’un doldurduğu tablo, programın içindeki yerine yazılır. Artık M33 vring adreslerini kendi belleğinden okuyabilir.

    Neden? Bu satırdan sonra Linux tabloyu bu kopyada günceller. M33’ün okuyacağı “durum” da burada.

    linux/drivers/remoteproc/remoteproc_core.c
    1291memcpy(loaded_table, rproc->cached_table, rproc->table_sz);1292rproc->table_ptr = loaded_table;
  7. M33 çalışmaya başlar

    M33 reset’ten çıkar. Zephyr iki thread başlatır: main (telemetri, öncelik 0) ve link_task (RPMsg, öncelik 5).

    Neden? Dikkat: M33 şu an çalışıyor ama Linux’un kanal sürücüsü henüz hazır değil. M33’ün beklemeyi bilmesi gerekiyor.

    linux/drivers/remoteproc/remoteproc_core.c
    1303ret = rproc->ops->start(rproc);
  8. Linux’un RPMsg sürücüsü bağlanır

    Aygıt bulundu, virtio_rpmsg_bus modülü yüklendi.

    Neden? Bu adım M33 başladıktan SONRA olur; kodda da sıra böyle.

    linux/drivers/remoteproc/remoteproc_core.c
    1310ret = rproc_start_subdevices(rproc);
  9. Linux 8 boş tampon verir

    Linux vring0’a 8 boş tampon koyar. M33’ten gelecek mesajlar bunlara yazılacak.

    Neden? 100 Hz’de 8 tampon 80 ms pay demektir.

  10. Durum: DRIVER_OK, ardından haber

    Linux tabloya “hazırım” yazar, sonra IPCC ile M33’e kesme gönderir.

    Neden? Önce durum, sonra haber. M33’ün haberi kaçırsa bile durumu okuyabilmesi bu sıraya dayanır.

    virtio_rpmsg_bus virtio0: rpmsg host is online
  11. Sonuç: M33 ayakta

    Linux tarafı bitti. link_task’ın devamı bir sonraki animasyonda.

    rproc-virtio rproc-virtio.3.auto: registered virtio0 (type 7) remoteproc remoteproc1: remote processor m33 is now up
✓

Açılışı anladım

Kartın günlüğünde creating channel satırı rpmsg host is online satırından önce çıktı. Çünkü M33, Linux hazır işaretini koyar koymaz kanalı duyurdu; Linux kendi satırını biraz sonra yazdı.
